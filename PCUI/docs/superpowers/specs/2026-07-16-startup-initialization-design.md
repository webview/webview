# PCUI 程序初始化页设计规格

日期：2026-07-16  
状态：已确认

## 1. 背景与目标

PCUI 最终由 WebView2 承载。应用冷启动时需要先展示一个独立、精致的初始化页面，在主题、语言、用户偏好、工作空间数据以及宿主连接准备完成后，才进入主工作区。

本次设计目标：

- 使用已经确认的“明亮现代 SaaS + 品牌分栏”视觉方向。
- 左侧保留轻量品牌动画，右侧展示真实初始化状态和进度。
- 初始化成功后进入仪表盘，不提前露出主界面。
- 初始化失败时停留在可恢复页面，提供重试与退出。
- 加载中和失败状态都始终提供关闭按钮。
- 在浏览器开发环境和 WebView2 正式环境中均可安全运行。
- 不破坏现有 PrimeVue 主题、多语言、侧栏和窗口控制结构。

本次不包含真实后端 API 设计；工作空间数据加载先通过可替换的初始化步骤接口承载，后续可接入实际服务。

## 2. 用户体验与视觉结构

初始化页使用全窗口双栏布局，不套用 `DefaultLayout`，因此不显示主界面的侧栏、顶栏或内容导航。

初始化内容直接铺满应用窗口，不增加“正常初始化 / 加载中”或“初始化失败 / 需要处理”之类的顶部演示白条；运行状态仅通过右侧正文、进度和错误内容表达。

### 2.1 左侧品牌区

- 使用现有主色系的明亮靛蓝渐变，占页面约 42%。
- 展示 Northstar 品牌标识、产品名和 `Desktop Workspace` 副标题。
- 使用低干扰动画：轨道缓慢旋转、少量光点漂浮、品牌图形轻微呼吸。
- 动画只使用 `transform` 和 `opacity`，避免高频重排。
- 当系统设置 `prefers-reduced-motion: reduce` 时关闭循环动画。
- 初始化失败后，动画停止或明显减弱，让用户理解流程已经中断。

### 2.2 右侧状态区

加载状态包含：

- 英文状态眉题与中文主标题。
- 当前初始化步骤说明。
- 0–100% 的真实步骤进度。
- 右上角始终可见的关闭按钮。

失败状态包含：

- 明确的失败图标、标题和可理解的原因。
- 失败叹号缩小后放在英文状态提示左侧，不单独悬浮，也不挤占中文标题宽度。
- 稳定错误码，例如 `HOST_TIMEOUT` 或 `WORKSPACE_LOAD_FAILED`。
- 主按钮“重试初始化”。
- 次按钮“退出程序”。
- 右上角关闭按钮继续可用。

失败状态不使用 Toast 作为主要承载，避免错误信息一闪而过。

## 3. 初始化状态机

初始化状态统一放在启动状态 Store 中，避免页面组件自行拼接异步状态。

状态定义：

- `idle`：尚未启动，仅用于初始建立状态。
- `running`：正在执行初始化步骤。
- `success`：所有步骤成功，准备跳转主页面。
- `failed`：步骤异常或总超时，等待用户重试或退出。

主要状态数据：

- `status`
- `currentStep`
- `completedSteps`
- `progress`
- `errorCode`
- `errorMessageKey`
- `attempt`

状态转换：

```text
idle -> running -> success -> dashboard
          |          
          +-> failed -> running（重试）
                 |
                 +-> close（退出）
```

同一时间只允许一个初始化任务运行。用户快速重复点击“重试”时，后续点击被忽略，防止多个任务同时修改状态。

## 4. 初始化流程

采用“真实初始化 + 最短展示时间 + 总超时”策略。

建议步骤与进度权重：

1. 应用主题和多语言偏好：20%。
2. 读取本地用户配置：20%。
3. 准备工作空间数据：35%。
4. 检查 WebView2 宿主通道或浏览器降级环境：25%。

每完成一步才更新到对应进度，不使用定时器伪造持续增长。最终成功时进度为 100%。

时间规则：

- 最短展示时长：1200ms，避免页面闪烁。
- 总初始化超时：8000ms。
- 初始化步骤和最短展示计时并行进行。
- 所有步骤完成且达到最短展示时长后才跳转。
- 超时或任一步骤抛出错误时进入 `failed`。

重试会清空上次错误、进度和步骤状态，增加 `attempt` 后重新运行完整流程。

## 5. 路由与生命周期

- 新增顶级路由 `/startup`，不嵌套任何现有布局。
- 冷启动默认入口重定向到 `/startup`。
- 初始化成功后调用 `router.replace({ name: 'dashboard' })`，避免用户按返回键再次进入启动页。
- 应用本次运行完成初始化后，访问 `/startup` 直接返回仪表盘。
- 用户在主工作区内切换页面不会重复初始化。
- 浏览器整页刷新视为一次新的应用启动，会重新显示启动页；这与 WebView2 重新装载 UI 的行为一致。
- 登录、无权限和 404 路由仍保持原结构，不由启动页负责鉴权页面展示。

## 6. 主题与多语言

现有 `useTheme()` 和 `useLocale()` 均在 `DefaultLayout`、`AuthLayout` 内调用。为了让独立启动页也立即使用持久化偏好，将它们统一提升到 `App.vue`：

- 根组件负责一次性应用主题和语言。
- `DefaultLayout`、`AuthLayout` 移除重复调用，避免重复监听系统主题。
- 启动页所有文字进入 `zh-CN.ts` 和 `en-US.ts`。
- 中文为默认语言，英文文案必须完整可用。
- 错误信息使用稳定的 i18n key，错误码本身不翻译。

## 7. WebView2 与关闭行为

继续使用现有 `windowBridge`，不在 Vue 页面中直接访问 `window.chrome.webview`。

关闭规则：

- 右上角关闭按钮和失败页“退出程序”均调用 `windowBridge.close()`。
- 在 WebView2 中发送 `{ type: 'window:close' }`，由宿主关闭窗口。
- 普通浏览器没有宿主通道时，调用安全完成且不抛异常，便于 Vite 预览和测试。

宿主检测规则：

- `windowBridge` 增加只读的宿主可用性能力，初始化服务通过桥接层检查，不直接读取全局对象。
- WebView2 环境存在通道时视为宿主连接已建立。
- 普通浏览器环境视为开发降级模式，该步骤成功完成，不显示失败。
- 未来如需严格的 C# 宿主握手，可在桥接层扩展 `app:initialize` / `app:ready` 消息，不改变启动页组件接口。

## 8. 组件与代码边界

计划新增：

- `src/views/startup/StartupView.vue`：只负责渲染状态、触发初始化、重试和退出。
- `src/stores/startup.ts`：保存启动状态并防止并发初始化。
- `src/services/initializeApp.ts`：编排初始化步骤、最短展示时间和总超时。
- 启动页相关测试文件。

计划修改：

- `src/App.vue`：在根层应用主题和语言。
- `src/layouts/DefaultLayout.vue` 与 `src/layouts/AuthLayout.vue`：移除重复偏好监听。
- `src/router/routes.ts`：新增启动路由、调整默认入口，并按此前确认为每个功能页路由补充中文代码注释。
- `src/config/navigation.ts`：为每个导航按钮补充对应功能页用途注释。
- `src/bridge/windowBridge.ts`：增加宿主可用性查询，保持原有窗口消息兼容。
- `src/locales/zh-CN.ts` 与 `src/locales/en-US.ts`：增加启动页文案。
- `src/styles/main.css`：增加启动页视觉样式、响应式规则和减少动画规则。

业务逻辑不得放进 CSS 或模板事件表达式；初始化编排和视图展示保持分离，便于后续替换真实服务。

## 9. 可访问性与窗口适配

- 关闭、重试、退出均使用原生 `button`，提供明确的 `aria-label`。
- 键盘焦点样式清晰，失败后焦点进入错误标题或“重试初始化”按钮。
- 进度区域使用 `role="progressbar"` 及 `aria-valuenow`。
- 错误区域使用 `role="alert"`，使辅助技术及时获知失败。
- 适配常见 PC 窗口尺寸；窄窗口下改为上下布局，优先保证操作按钮可见。
- 初始化页不刻意保留传统标题栏，但右侧顶部预留 WebView2 可拖拽区域，并避免覆盖关闭按钮交互区。

## 10. 测试与验收标准

单元测试覆盖：

- 初始化步骤按顺序执行并计算正确进度。
- 最短展示时间未达到时不提前跳转。
- 8 秒总超时进入失败状态并产生稳定错误码。
- 任一步骤异常进入失败状态。
- 重试清空错误并重新执行，重复点击不会并发运行。
- WebView2 和普通浏览器两种宿主检查结果均符合设计。
- 关闭和退出均调用窗口桥接。
- 根层主题、多语言只初始化一次。
- 默认路由先进入启动页，成功后替换到仪表盘。

视觉与交互验收：

- 正常加载和失败两种状态与确认稿一致。
- 关闭按钮在两种状态下都完整、可点击且不被拖拽区域拦截。
- 失败后加载动画停止或降级，重试后恢复。
- 中文和英文下无溢出、遮挡或明显布局跳动。
- 亮色、暗色主题均清晰可读。
- `prefers-reduced-motion` 下无循环动画。

完成验证命令：

```bash
npm run test:run
npm run type-check
npm run build
```
